# 台股橫斷面量化倉儲與排序系統

自用工具。從 TWSE 官方資料建立全市場面板，計算橫斷面因子，產出每日排序與**帶成績單的**看漲／看跌名單。

## 設計原則

**先蓋計分板，再蓋選手。**

這類系統的標準失敗模式是「做訊號 → 回測漂亮 → 上線 → 虧錢」。唯一的防線是在對任何訊號產生感情之前，先把測量工具蓋好並驗證過。所以 `validate.py` 先於 `rank.py` 完成，而且有一道自檢：

```bash
python run.py validate
```

第一步會餵 20 組**純隨機訊號**進框架。如果隨機雜訊被報成顯著，框架就是壞的，後面所有數字都不能信，程式會直接停住。

這個自檢在開發時真的抓到了一個 bug：Newey-West 的自協方差估計在小樣本下很吵，負值加總會把變異數壓到比 iid 估計還小，反而**放大** t 值。修法是改用非重疊抽樣做主要檢定，並強制 NW 變異數不得低於 iid 估計。

## 架構

```
L1 ingest.py    每日全市場快照。冪等、可中斷續跑、原始 JSON 不可變歸檔
L2 parse.py     正規化。所有 TWSE 欄位陷阱都在這一層擋掉
L3 store.py     DuckDB。從 raw/ 全量重建，永遠可重現
L4 factors.py   因子計算。滾動視窗一律不含當日
L5 validate.py  計分板。IC / 非重疊檢定 / 區塊自助法 / 十分位回測（扣成本）
L6 rank.py      等權合成 + 每日排序
   report.py    單檔 HTML，雙擊開啟
```

## 資料來源

| 資料集 | API | 內容 |
|---|---|---|
| `mi_index` | `MI_INDEX?type=ALLBUT0999` | 全市場日行情 OHLCV + 本益比。**一次請求 1,379 檔** |
| `t86` | `fund/T86` | 三大法人買賣超 |
| `bwibbu` | `BWIBBU_d` | 本益比／殖利率／股價淨值比 |
| `margin` | `marginTrading/MI_MARGN` | 融資融券餘額 |
| `exrights` | `exRight/TWT49U` | 除權息權值+息值（報酬調整用） |

**資料軸的選擇很關鍵**：用「每天抓全市場」而非「每檔抓月資料」。回補 5 年前者約 1,225 次請求（1 小時），後者要 65,520 次（54 小時）且幾乎必被擋。

## 已處理的陷阱

這些都是實測踩到的，不是理論擔憂：

1. **MI_INDEX 的漲跌價差是絕對值**，正負號在另一個 HTML 欄位（`<p style= color:green>-</p>`）。直接讀會得到全市場天天漲。
2. **除權息標記** 在同一個 HTML 欄位（`<p>X</p>`）；STOCK_DAY 則是 `X0.00` 前綴，位置不同。
3. **除權息調整**：MI_INDEX 在除權息日只回報 `change=0`，無法分離配息與真實漲跌。必須用 TWT49U 的除權息參考價。實測 8,667 筆事件平均調整 3.73%，**24.8% 超過 5%**。不調整會製造出「高殖利率 = 低報酬」的假訊號。
4. **回傳結構是 `tables[]` 陣列**，個股表位置不固定 → 用欄位簽章尋找，不寫死索引。
5. **本益比** 對虧損公司是 `-`、對 ETF 是 `0.00`，都不是數值 0。
6. **存活者偏誤**：universe 必須從每日快照建構。實測 2023→2026 三年半就有 15 檔普通股消失，且不成比例地是出事的公司。
7. **流動性**：26% 的證券日成交 < 10 萬股，報酬是買賣價差跳動的產物。門檻用**事件當日**的 20 日均額判定，不是今天的。
8. **證券分類**：1,379 檔裡只有 1,089 檔普通股。ETF、特別股、TDR 的報酬驅動來源完全不同，不可混排。

## 統計方法

- **市場中性**：所有前瞻報酬先做橫斷面去均值。不這樣做，量到的是大盤 beta 不是訊號。
- **非重疊抽樣**：h 日前瞻報酬每 h 天取一個橫斷面。這是主要檢定依據；重疊版本只當對照。
- **區塊自助法**：不依賴常態假設，對自相關穩健。
- **交易成本**：來回 0.6%（證交稅 0.3% + 手續費 2×0.1425%），十分位回測強制扣除。
- **樣本門檻**：獨立期數 < 30 不報顯著性，< 100 標記「僅供參考」。

## 在一台新電腦上開始

版控裡<b>沒有</b> `data/` 與 `raw/`，因為兩者都是可重現的衍生物，而且 DuckDB
單檔 873 MB 超過 GitHub 100 MB 的硬限制。所以剛 clone 下來的專案<b>還不能跑</b>，
要先把資料補起來。

```bash
git clone https://github.com/hsinfuyeh/twse-quant.git
cd twse-quant
pip install -r requirements.txt

# 從零回補。7,492 次請求、間隔 2.5 秒 -> 約 5.2 小時。
# 冪等可中斷：斷了直接重跑，已經抓過的會跳過。
python ingest.py

python -c "import store; store.build()"
```

只想先跑起來看看的話，回補最近 300 個交易日就夠算出當日的所有因子
（最深的回看視窗是 252 天），約 50 分鐘：

```bash
python ingest.py mi_index,bwibbu,t86,margin 300
python -c "import store; store.build()"
```

差別在於：300 天版本足以產出當日名單，但<b>不足以重跑驗證</b> ——
`validate.py` 的十分位回測與非重疊檢定需要完整的 1,873 天樣本。

之後日常使用直接雙擊 `dashboard.bat`，資料會自己跟上，不需要再手動跑任何東西。

## 使用

```bash
python run.py ingest            # 回補（可中斷續跑）
python run.py build             # raw -> DuckDB
python run.py validate          # 自檢 + 因子驗證
python run.py rank              # 上市普通股排序 HTML
python run.py rank-etf          # ETF 排序（獨立宇宙與因子集）
python run.py stock 2330 2317   # 個股 K 線觀察報告
python run.py daily             # 每日跑這個：增量更新 + 重建 + 出全部報告
python tests.py                 # 29 項正確性測試
```

## 三種產出

**個股報告** (`stock_XXXX.html`) — 30 日 K 線＋成交量、六種規則、黃色圓點、
命中後 1/3/5/10 日報酬、歷史案例統計。每個報酬同時呈現**絕對報酬**與
**相對同日全市場中位數的超額報酬**；只看絕對報酬會誤導，因為多頭期間
任何規則的絕對報酬都是正的。案例數 < 30 直接標示不具統計意義。

**普通股排序** (`ranking_YYYY-MM-DD.html`) — 等權合成分數的看漲／看跌名單，
強制附成績單。

**ETF 排序** (`ranking_etf_YYYY-MM-DD.html`) — 獨立宇宙（見下）。

## ETF 的處理

253 檔 ETF/ETN 只納入 **domestic（台股一般型）+ dividend（高股息）**，約 93 檔。

排除的原因（`factors.py` 的 `ETF_SUBCATS`）：

| 次類 | 檔數 | 排除理由 |
|---|---|---|
| leveraged / inverse | 42 | 路徑相依衰減，盤整期期望報酬結構性為負，放進看漲名單是主動有害 |
| foreign | 52 | 驅動因子是海外股市，完全不在 TWSE 資料裡 |
| bond | 8 | 追美債殖利率 |
| active | 27 | 2025 後才出現，歷史太短無法回測 |

ETF 只用價格類因子。**不用價值因子**（股價淨值比被套利釘在 1.00，無訊息量）、
**不用法人因子**（ETF 的三大法人買賣超主要是造市商申贖，不是方向性看法，
混進去會汙染整個模型）。

缺口：折溢價（vs 淨值）是 ETF 唯一真正有效且可交易的訊號，但淨值不在 TWSE，
需另接投信投顧公會。目前沒有。
橫斷面偏窄（早年平均每日僅約 20 檔通過流動性門檻），程式會自動降級成 top/bottom 5。

## 合理期待

台股橫斷面因子 IC 大約 0.02–0.05。實務語言：**不是「找出會漲的股票」，是「在 1,000 檔裡把勝率從 50% 推到 53%」。**

10 日換倉、全額換手的來回成本是 1.2%，所以毛價差必須超過 1.2% 才有意義——這是很高的門檻，大多數因子過不了。

會有連續 6–12 個月完全失效的期間。
