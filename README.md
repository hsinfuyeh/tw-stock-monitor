# 台股觀測 · tw-stock-monitor

自用工具。從 TWSE 官方資料建立全市場面板，計算橫斷面因子，產出每日排序與**帶成績單的**看漲／看跌名單。

## 設計原則

**先蓋計分板，再蓋選手。**

這類系統的標準失敗模式是「做訊號 → 回測漂亮 → 上線 → 虧錢」。唯一的防線是在對任何訊號產生感情之前，先把測量工具蓋好並驗證過。所以 `validate.py` 先於 `rank.py` 完成，而且有一道自檢：

```bash
python run.py validate
```

第一步會餵 20 組**純隨機訊號**進框架。如果隨機雜訊被報成顯著，框架就是壞的，後面所有數字都不能信，程式會直接停住。

這個自檢在開發時真的抓到了一個 bug：Newey-West 的自協方差估計在小樣本下很吵，負值加總會把變異數壓到比 iid 估計還小，反而**放大** t 值。修法是改用非重疊抽樣做主要檢定，並強制 NW 變異數不得低於 iid 估計。

## 架構

```
L1 ingest.py    每日全市場快照。冪等、可中斷續跑、原始 JSON 不可變歸檔
L2 parse.py     正規化。所有 TWSE 欄位陷阱都在這一層擋掉
L3 store.py     DuckDB。從 raw/ 全量重建，永遠可重現
L4 factors.py   因子計算。滾動視窗一律不含當日
L5 validate.py  計分板。IC / 非重疊檢定 / 區塊自助法 / 十分位回測（扣成本）
L6 rank.py      等權合成 + 每日排序
   report.py    單檔 HTML，雙擊開啟
```

## 資料來源

| 資料集 | API | 內容 |
|---|---|---|
| `mi_index` | `MI_INDEX?type=ALLBUT0999` | 全市場日行情 OHLCV + 本益比。**一次請求 1,379 檔** |
| `t86` | `fund/T86` | 三大法人買賣超 |
| `bwibbu` | `BWIBBU_d` | 本益比／殖利率／股價淨值比 |
| `margin` | `marginTrading/MI_MARGN` | 融資融券餘額 |
| `exrights` | `exRight/TWT49U` | 除權息權值+息值（報酬調整用） |
| （不進倉儲） | `exRight/TWT48U` | 除權除息預告表 —— 「即將除權息」榜單用。TWT49U 只有已經發生的，不能拿來排未來 |
| （不進倉儲） | `holidaySchedule` | 市場開休市日期 —— 網頁算「落後幾個交易日」時扣掉休市日 |

**資料軸的選擇很關鍵**：用「每天抓全市場」而非「每檔抓月資料」。回補 5 年前者約 1,225 次請求（1 小時），後者要 65,520 次（54 小時）且幾乎必被擋。

**目前資料範圍**：2008-01-02 ~ 今天，4,597 個交易日。行情／估值／融資券 2008 年起齊全；
三大法人 2012-05 起（TWSE 沒有更早的）；月營收 2007 年起（公開資訊觀測站月報表，
每月一頁、全部上市公司，含後來下市的，所以沒有存活者偏誤；每次 CI 更新會補抓最近兩個月）。
除權息 16,371 筆也補到 2008 —— 少了它，除息的價格落差會被當成下跌，
每年系統性低估 3-4% 的報酬。

## 已處理的陷阱

這些都是實測踩到的，不是理論擔憂：

1. **MI_INDEX 的漲跌價差是絕對值**，正負號在另一個 HTML 欄位（`<p style= color:green>-</p>`）。直接讀會得到全市場天天漲。
2. **除權息標記** 在同一個 HTML 欄位（`<p>X</p>`）；STOCK_DAY 則是 `X0.00` 前綴，位置不同。
3. **除權息調整**：MI_INDEX 在除權息日只回報 `change=0`，無法分離配息與真實漲跌。必須用 TWT49U 的除權息參考價。實測 8,667 筆事件平均調整 3.73%，**24.8% 超過 5%**。不調整會製造出「高殖利率 = 低報酬」的假訊號。
4. **回傳結構是 `tables[]` 陣列**，個股表位置不固定 → 用欄位簽章尋找，不寫死索引。
5. **本益比** 對虧損公司是 `-`、對 ETF 是 `0.00`，都不是數值 0。
6. **存活者偏誤**：universe 必須從每日快照建構。實測 2023→2026 三年半就有 15 檔普通股消失，且不成比例地是出事的公司。
7. **流動性**：26% 的證券日成交 < 10 萬股，報酬是買賣價差跳動的產物。門檻用**事件當日**的 20 日均額判定，不是今天的。
8. **證券分類**：1,379 檔裡只有 1,089 檔普通股。ETF、特別股、TDR 的報酬驅動來源完全不同，不可混排。

## 統計方法

- **市場中性**：所有前瞻報酬先做橫斷面去均值。不這樣做，量到的是大盤 beta 不是訊號。
- **非重疊抽樣**：h 日前瞻報酬每 h 天取一個橫斷面。這是主要檢定依據；重疊版本只當對照。
- **區塊自助法**：不依賴常態假設，對自相關穩健。
- **交易成本**：來回 0.6%（證交稅 0.3% + 手續費 2×0.1425%），十分位回測強制扣除。
- **樣本門檻**：獨立期數 < 30 不報顯著性，< 100 標記「僅供參考」。

## 在一台新電腦上開始

版控裡<b>沒有</b> `data/` 與 `raw/`，因為兩者都是可重現的衍生物，而且 DuckDB
單檔 284 MB 超過 GitHub 100 MB 的硬限制。所以剛 clone 下來的專案<b>還不能跑</b>，
要先把資料補起來。

```bash
git clone https://github.com/hsinfuyeh/tw-stock-monitor.git
cd tw-stock-monitor
pip install -r requirements.txt

# 從零回補到 2008（4,597 個交易日 × 4 個資料源），約 18,000 次請求、
# 間隔 2.5-5 秒 -> 約 14 小時。實測 2026-09 跑完一次。
# 冪等可中斷：斷了直接重跑，已經抓過的會跳過。
python ingest.py

python -c "import store; store.build()"
```

只想先跑起來看看的話，回補最近 300 個交易日就夠算出當日的所有因子
（最深的回看視窗是 252 天），約 50 分鐘：

```bash
python ingest.py mi_index,bwibbu,t86,margin 300
python -c "import store; store.build()"
```

差別在於：300 天版本足以產出當日名單，但<b>不足以重跑驗證</b> ——
`validate.py` 的十分位回測與非重疊檢定需要完整的 4,597 天樣本。

之後日常使用直接雙擊 `dashboard.bat`，資料會自己跟上，不需要再手動跑任何東西。

## 雲端更新（GitHub Actions，沒有定時排程）

2026-10-01 起**沒有任何定時排程**（GitHub 排程、Cloudflare 定時觸發、本機工作排程都拿掉了）。
資料只在兩種時候更新，都經過自己的 Cloudflare Worker（`cloudflare/`）觸發 GitHub Actions：

- **打開網頁**：網頁照「現在幾點、今天開不開市」（`meta.json` 的 `holidays`）算出應該要有哪一天的資料
  —— 交易日 14:40 後是當天、21:40 後當天的融資券也該進來了（`margin_same_day`）、其他時間是上一個交易日。
  網站比那個舊就自動觸發（`trigger=cron`，比照舊的排程：證交所還沒發完就安靜略過、當天發佈過就不重做）。
  同一個瀏覽器 20 分鐘內只自動觸發一次，Worker 另有 5 分鐘冷卻與「有更新在跑就不觸發」。
- **按右上角 ⟳**：同上，另外先在瀏覽器裡讀 PTT 算社群聲量一起送來；資料沒變時走快速通道（約 1 分鐘）。

也可以在 Actions 分頁按 Run workflow，或 `gh workflow run update.yml`（等同按 ⟳，不含社群聲量）。
勾 `backfill` 是「補歷史」：補上櫃與主動式 ETF 的舊資料，約 40 分鐘，期間其他更新會排隊（見「上櫃股票與主動式 ETF」）。
平常的更新不補歷史，當天第一次更新約 4–5 分鐘（舊版每次順便補歷史，要 12–14 分鐘）。

不定在 13:30 收盤當下，是因為那時資料根本還不存在（行情約 14:30 發布，估值與三大法人更晚）。

**名單成績不會因為沒人看而少一天**：某個交易日一整天都沒人打開網頁，那天的名單當下沒被記下來；
下一次更新時 `stable.backfill` 用當天的資料補算（第一份快照之後缺的交易日都會補，一次最多 10 天，標「補算」）。
處置股名單只查得到「現在」的，所以補算的日子沒有套用處置股排除，頁面上有註明。

```
按下 Run workflow
    ↓
還原倉儲（Actions 快取；快取失效就從 Release 種子下載）
    ↓
抓缺的交易日
    ↓
資料齊備閘門  ← 三個核心資料源沒齊就停在這裡，不發佈
    ↓
重建倉儲 -> publish.py -> GitHub Pages
```

<b>那道閘門是整個流程最重要的一步。</b>TWSE 各資料源發布時間不同（行情約
14:30，估值與三大法人更晚），所以每天下午都有一段時間「行情有了、估值還沒
有」。若在那時發佈，殖利率那層排除規則會因為缺值而靜默失效，候選名單會從
221 檔虛胖成 407 檔 —— 而且畫面上沒有任何跡象。本機版真的中過一次。

閘門擋下時工作流程是<b>綠色的「已跳過」而不是紅色失敗</b>：那不是錯誤，
是刻意不發佈；標成失敗會讓人開始習慣性忽略紅色叉叉。晚點再按一次即可。

**不會安靜地漏掉日子**（2026-10-03）：
- 一次補好幾天、中間某一天沒抓齊（例如證交所忙的時候三大法人回錯誤）時，只寫到那天之前，
  後面齊了的也先不寫，下次從缺的那天重試（`ci_update.ready_prefix`）。舊版照寫後面的日子，
  缺的那天就永遠不會再補。
- 每次更新都檢查倉儲最近 60 個交易日，三張核心表是不是每天都有；有洞就重抓（`heal_holes`），
  補不起來會在執行摘要留警告。
- 證交所還沒發完時**按 ⟳**：新的那天先不寫，但照樣發佈（快速通道，只換社群聲量），
  瀏覽器讀好的 PTT 聲量不會丟掉；網頁跑完會確認網站真的換了才說「更新完成」。自動觸發照舊略過。
- 月營收有新的月份或更正時不走快速通道，完整產出一次（`refresh_revenue` 比對內容指紋）。

### 第一次設定

CI 的 runner 每次都是乾淨的，而從零回補要十幾個小時（會超過 job 上限），
所以要先放一份倉儲種子：

```bash
python seed.py          # 把壓實後的倉儲（打包後 180 MB）上傳成 Release
python seed.py --check  # 只看狀態
```

種子不是不可取代的資料 —— 它完全可以從 `raw/` 重建。改了解析邏輯之後，
在本機重建再種一次即可。

之後不用再手動種：每次更新存完快取後，workflow 會跑 `python seed.py --if-older 7`，
種子超過 7 天就用雲端手上的倉儲重新上傳（一週最多一次）。這是為了快取被清掉的時候 ——
Actions 快取 7 天沒用就會被刪（例如連假沒人打開網站），那時從種子冷啟動，`ci_update`
會把種子最後一天之後的交易日全部補上（舊版只看最近 20 天，種子太舊會安靜地漏掉中間）。


## 網站

頁面只有一份（`site/`），公開網站（GitHub Pages）和本機（`python server.py` / `dashboard.bat`）共用。
網址不帶 `.html`（`/short`、`/stock?c=2330`，首頁就是 `/`）：GitHub Pages 會自己對到 `short.html`，本機的 `server.py` 也有同樣的路由；舊的 `xxx.html` 書籤照樣能開，網址列會自動換成乾淨的版本。
導覽列：首頁、今日名單、名單成績、回測報告、其他排行（每張 10 筆，左側清單裡也有中長期候選池）。
首頁只有一個查個股的大搜尋框；今日名單、回測報告、名單成績是「穩定強勢股」（`stable.py`，見下一節）。
頂端的「資料落後幾個交易日」會扣掉週末與證交所公布的休市日（`ingest.holidays()`，放在 `meta.json` 的 `holidays`）。本機多一個功能：資料落後時按「立即更新」。
改樣式請改 `webui_css.py` 再執行 `python webui_css.py`；名詞解釋在 `webui.GLOSSARY`。

## 研究驗證（`barrier.py`、`study_*.py`、`RESEARCH_LOG.md`）

依《短線選股工具_研究驗證與實作規格_2026-09-18》建立的驗證流程：

- `barrier.py` — 規格書的特徵字典 ＋ 10 日 / +5% 先觸及標籤（triple-barrier）。
  隔天開盤進場、跳空以開盤價成交、同日碰兩邊算停損先到、一字漲停買不到、
  鎖跌停當天賣不掉，損益含除權息。
- `study.py` — 統一入口（`python study.py all`）。特徵面板算一次快取在
  `data/study_panel.pkl`，倉儲更新會自動重算。每一輪吃的參數都寫死在腳本裡、
  不跟著網站預設走，否則以後改了設定，RESEARCH_LOG 的數字就重現不出來。
- `study_spec.py` — 事前登記的 23 組（baseline、M1 突破、M2 回檔、M3 營收事件、
  M4 反轉、PRD 對照），walk-forward 選參數、2026 當 holdout。
- `study_exit.py` / `study_hold.py` / `study_bench.py` — 停損、目標與持有期、
  以及改用 0050 當基準的比較。
- `RESEARCH_LOG.md` — **所有**測過的組合與結果（不只最好的），含事前登記的假設。

主要結論（2026-09 用 2008–2026 共 18 年、67,128 筆交易重跑過）：
停損越緊越虧（每個策略、每個期間都一樣）；設目標價會砍掉右尾；
選股贏得過「平均個股」但**贏不過 0050**（每筆少賺 0.44%，t = −5.47）。
2008–2018 那 11 年完全沒參與過調參，數字卻跟樣本外一致 —— 不是運氣問題。

長樣本也推翻了幾個短樣本看起來有效的東西：M1 突破 +0.086 → +0.007、
M2 回檔從持平 → −0.228（t = −5.38）、我自己加的波動門檻對報酬的方向在
2019 前後相反。細節都在 RESEARCH_LOG 第 7 輪。

## 穩定強勢股名單（`stable.py`，網頁「首頁／今日名單／名單成績／回測報告」，2026-09-26 起）

每天 10 檔「動能強但穩定」的上市股票，看接下來 10 個交易日能不能漲 5%。只給名單，不給停利停損或買賣建議。
定義、判定與結果都在 RESEARCH_LOG 第 11 輪（事前登記）。

- **範圍與排除**：成交額前 300 名、收盤 ≥ 10 元；刷掉 ATR > 3.5%、近 20 日漲停 ≥ 2 次、跳空 ≥ 4% 兩次以上、
  爆量 5 倍、60 日漲超過 50%、融資 5 日增 20% 以上、鎖死。每天名單另外刷掉處置股、近 30 日注意股、全額交割股
  （`risk_lists.recent_attention`；這三份沒有歷史，回測不套）。
- **打分**：趨勢平滑度、漲得有效率、收紅比例、均線結構、接近一年高、比大盤強、法人持續買、籌碼乾淨、營收優於預期，
  在穩定池裡排百分位、等權平均；前 10 名、同產業最多 3 檔。
- **評分標準**：隔天開盤為基準，10 個交易日內收盤先到 +5% 算中、先到 −5% 算倒；停牌下市算倒。
- **回測**（2008–2025）：名單中 27.2%／倒 23.7%，穩定池隨便挑 22.8%／22.8%；「中減倒」多 3.5 個百分點（t 5.1），
  兩段期間都成立、也贏過波動相同的隨機。2026 年沒有比池子好。回測只當淘汰關卡（資料被前 10 輪看過）。
- **名單成績**：每天的名單存到 `snapshots/stable/`（只有 CI 寫，本機要寫設 `FORWARD_PERSIST=1`），
  10 個交易日後自動對答案；滿 250 天、t ≥ 3 才算有效。
- **更新時機**：交易日 14:40 後有人打開網頁就更新第一版（融資用前一天的）；融資券約 21:30 公布，21:40 後有人打開網頁會再更新一次，這一版為準（`ci_update.refresh_margin`，也會補抓前幾天漏掉的融資券）。沒人看的交易日由下一次更新補算（`stable.backfill`）。
- 舊的短線規則（下一節）與 Arm 0–8 前瞻實測 2026-09-26 起停止，程式與快照保留供研究查閱。

## （已停用）短線盤後選股（`shortterm.py`、舊「今日清單／策略追蹤」）

依 `stock-screener-PRD.pdf` 實作。四個條件各 25 分、不必全部符合：月營收年增 ≥ 20%
（創 12 個月新高再加分）、投信或外資連買 ≥ 3 天、收盤突破前 20 日高且量 ≥ 前 5 日均量
1.5 倍、收盤 > MA5 > MA10 > MA20。股票型 ETF 沒有月營收，用後三項換算成 100 分。
20 日均量 < 1,000 張、ATR% < 2.5% 直接排除。所有門檻與權重都能在網頁上調，
調參只在瀏覽器裡重算分數。

- **波動門檻**（ATR% ≥ 2.5%）：20 個交易日要漲 5.6% 才能淨賺 5%，
  平常一天只動 1% 的股票很難做到，但手續費和稅一樣要付。
  <b>只對「達標率」有證據</b>（每個年代都提高，44.6%→51.1%、50.5%→58.2%）；
  對「報酬」則方向不一致（2019 後變好、2008–2018 變差），
  這是只用近期資料挑參數的典型結果，不能當成它能提高報酬。
- **參考價位**：停損 = 進場價 − 3 × ATR14（距離限制在 2%–10%）、
  目標 = 進場價 × (1 + 5% + 0.585%)（賣掉之後淨賺 5%）、最多抱 20 個交易日。
  兩個價位都以<b>實際成交價</b>為基準，網頁上另有換算工具。
- **取捨**（RESEARCH_LOG 第 6 輪）：設 5% 目標的達標率 60.8% 很漂亮，
  但對 0050 是 −0.37%（t = −2.75）；關掉目標價則是 −0.02%（t = −0.1）。
  停損從 1×ATR 到不停損全部測過，只要設目標那一排永遠為負。
  預設依使用者要求保留目標價，兩個數字都列在回測報告。
- **回測**：隔天開盤進場（不是 PRD 的當日收盤 —— 法人資料 15:00 後才有，當天收盤買不到），
  扣 0.585% 成本，和同期 0050 比。同時列出 PRD 的近 60 日與整段歷史，
  因為 60 日只相當於約 6 次獨立觀察。本機可以用自訂參數回測，公開網站只有預設參數的報告。
- **策略追蹤**（`forward.py`，規範 v1；網頁「策略追蹤」）：九個臂同時紙上跑 ——
  2026-09-22 起：Arm 0 現行版、Arm 1 不設目標、Arm 2 短期反轉（M4，持有 10 日、附「不停損」影子）、Arm 3 10 日版；
  2026-09-23 起（第 9 輪，最終判定 t ≥ 3）：Arm 4 只挑大型股、Arm 5 總分 ≥ 70、Arm 6 停損太寬不買、
  Arm 7 只看月營收不設目標、Arm 8 模型選股（`model.py`，逐年往前訓練的邏輯迴歸）。
  今日清單的參數區有五個方案的一鍵套用，網頁會逐一比對瀏覽器與 Python 選出的清單。
  每臂每天的清單存到 `snapshots/`（Arm 0 在根目錄，其他在 `snapshots/arm1..3/`），CI 會 commit 回 repo；
  沒產出的日子下次發佈時用當天已知的資料補算並標「補算」。快照檔只由 CI 寫（本機產網頁不寫，避免 git 衝突；
  真的要本機寫就設 `FORWARD_PERSIST=1`）。成績用規範第 5 節的資金規則算成組合
  （最多 3 檔、每筆風險 0.5%、一天新增 ≤ 1、單檔 ≤ 20%、同產業 ≤ 2、處置／注意／全額交割股不買、
  金額 > 日均成交額 1% 不買），判定用「組合買的每一筆 − 同期 0050」的平均與 NW t（跟回測頁同一套），
  第 120 天中期檢查、第 250 天最終判定，參數一改該臂重新起算。
- **處置股／注意股／全額交割股**（`risk_lists.py`）：每次發佈從 TWSE 抓（全額交割用 OpenAPI 的 TWT85U 變更交易），
  快取在 `raw/risklists/`。抓不到標 unavailable、注意股 0 筆標 pending（可能還沒公布），網頁會請你自己確認。
  補算缺日、以及前幾天名單還沒確定的，下次發佈會回頭重抓（最多 10 個交易日）再重標快照。
- **更新按鈕**（右上角 ⟳）：公開網站呼叫自己的 Cloudflare Worker（`POST /update`），由 Worker 用它保管的 GitHub 金鑰觸發更新，瀏覽器裡沒有金鑰、不用輸入任何東西。入口是公開的，所以 Worker 會擋掉「已有更新在跑」與「5 分鐘內觸發過」的要求。按下去時順便在瀏覽器裡讀 PTT 算社群聲量（見下方社群聲量）。
- **更新速度**：完整產出約 4 分鐘（載入 18 年面板、穩定名單與回測、一千多檔個股頁）。兩個加速：（1）**快速通道** —— 手動更新而行情、法人、融資券都沒有新資料時，workflow 還原「同一個資料日期、同一份程式碼」上次產出的 `site/data`（Actions 快取，鍵含程式碼雜湊），只跑 `python publish.py --social-only` 重算社群聲量兩張榜（約 3 秒），整次更新約 1 分鐘；改過程式或網頁檔、快取過期就自動退回完整產出。（2）**個股頁同時產生** —— CI（Linux）用 fork 分給 4 個子行程，產完抽樣 20 檔跟單獨重做的逐位元核對，不一樣就中止發佈；Windows 沒有 fork，本機照舊一檔一檔做。`PUBLISH_WORKERS=1` 可以關掉。
- **沒有定時排程**：GitHub 排程、Cloudflare 定時觸發、本機工作排程（`fallback.py`、`social_push.py`）都在 2026-09-30～10-01 拿掉了，改成打開網頁時自動檢查（見「雲端更新」）。
- **一致性**：評分在網頁（JS）與 Python 各有一份，頁面載入時會用預設參數比對兩邊的清單，
  對不上會在頁面頂端警告。改規則時兩邊要一起改。

## 社群聲量（只供參考，2026-09-29 加入）

`social.py`。「其他排行」的「社群聲量」分組有兩張榜：**聲量最高**（被提到最多次）、
**聲量暴增**（比自己前 20 個交易日平均放大最多，至少 5 次才列）。上市、上櫃普通股都列，不看成交量門檻；ETF 不列。
跟上櫃一樣**只顯示、不進選股、研究與前瞻實測**，抓不到也不擋發佈（頁面會寫「這次抓不到」）。

| 來源 | 狀態 | 說明 |
|---|---|---|
| PTT 股票板 | 使用中 | 公開網頁，但整站在 Cloudflare 後面：**GitHub 雲端主機直接連、或從 GitHub 呼叫自己的 Worker 代讀，都是 HTTP 403**（PTT 的防護看的是最初發起請求的來源；2026-09-29、09-30 實測）。從一般使用者的瀏覽器透過 Worker 代讀則是通的，所以**網頁按 ⟳ 更新時**，瀏覽器透過 Worker 讀最近 3 天的文章、自己算出次數（`site/assets/social.js`），跟著更新要求一起送進來，`social.apply_payload` 檢查後併入 `snapshots/social/ptt.json`（約 100 KB，逐格取大的）。不靠任何電腦的排程；沒有人按更新的日子，頁面會寫「PTT 資料停在哪天」。文章（標題＋內文）與每一則推文都算一次，推文照自己的時間戳算日期 |
| Threads | 有金鑰才啟用 | 只能走 Meta 官方 `keyword_search` API：要建 Meta App、`threads_keyword_search` 權限**通過審核**（沒過只搜得到自己的貼文），把金鑰放進 repo 的 Secret `THREADS_TOKEN`。額度 2,200 次 / 24 小時，所以只在晚上 21 點後那次排程、查 PTT 聲量前 400 檔 |
| Dcard | 不做 | 2026-10-03 不登入實測三條路都不通：家用網路直接讀 API 與網頁、經自己的 Worker 代讀（從腳本或瀏覽器呼叫都一樣）都是 Cloudflare 的 403「Attention Required」驗證頁；網頁裡的瀏覽器直接讀則被 CORS 擋（Dcard 不讓別的網站讀）。PTT 那條「瀏覽器經 Worker 代讀」的路對 Dcard 無效。剩下的只有登入或繞過驗證，前者有鎖帳號風險、後者不做 |

**統計期間**：上一個交易日之後到這個交易日的日曆日（連假的討論算進開市那天）。
**比對**：股票代號（前後不是數字、後面不接年／點／元／張這類單位）或名稱（長的優先：「長榮航」不會算成「長榮」）。
網頁端的比對（`social.js`）是照 `social.Matcher` 重寫的一份：規則從 `data/social_rules.json` 讀（不另外抄），開始前先跑檔案裡附的測試句，跟 Python 的答案對不上就不送。
兩字名稱是日常用語的（世界、中華、統一、大量、幸福…約 90 個，`social.AMBIGUOUS`）只認代號，
常用全名另外補回（世界先進、中華車…，`social.ALIASES`）；「東南亞」「海力士」「聯合報」先挖掉再比對。
**資料**：只存每天每檔的次數（`snapshots/social/ptt.json`），歷史留在版控裡；股票板一天約 35–50 篇。
**手動救援**：匯總檔的歷史掉了的時候，在家用網路跑 `python social.py 35`（Python 版爬蟲，直接連 PTT）可以一次補回 35 天，再自己 commit 那個檔；平常不會用到。
「暴增」要至少 5 個交易日的歷史才會出現。

研究上散戶關注突然升高的股票常常是短線過熱、之後反轉（Barber & Odean 2008；Da, Engelberg & Gao 2011），
所以頁面標成「今天的事實」並附警語；要當選股條件得先照 RESEARCH_LOG 的流程登記、回測。

## ETF 的處理

253 檔 ETF/ETN 只納入 **domestic（台股一般型）+ dividend（高股息）**，約 93 檔。

排除的原因（`factors.py` 的 `ETF_SUBCATS`）：

| 次類 | 檔數 | 排除理由 |
|---|---|---|
| leveraged / inverse | 42 | 路徑相依衰減，盤整期期望報酬結構性為負，放進看漲名單是主動有害 |
| foreign | 52 | 驅動因子是海外股市，完全不在 TWSE 資料裡 |
| bond | 8 | 追美債殖利率 |
| active | 27 | 2025 後才出現，歷史太短無法回測 |

ETF 只用價格類因子。**不用價值因子**（股價淨值比被套利釘在 1.00，無訊息量）、
**不用法人因子**（ETF 的三大法人買賣超主要是造市商申贖，不是方向性看法，
混進去會汙染整個模型）。

缺口：折溢價（vs 淨值）是 ETF 唯一真正有效且可交易的訊號，但淨值不在 TWSE，
需另接投信投顧公會。目前沒有。
橫斷面偏窄（早年平均每日僅約 20 檔通過流動性門檻），程式會自動降級成 top/bottom 5。

## 合理期待

台股橫斷面因子 IC 大約 0.02–0.05。實務語言：**不是「找出會漲的股票」，是「在 1,000 檔裡把勝率從 50% 推到 53%」。**

10 日換倉、全額換手的來回成本是 1.2%，所以毛價差必須超過 1.2% 才有意義——這是很高的門檻，大多數因子過不了。

會有連續 6–12 個月完全失效的期間。
